# 💬 Telecom Support Ticket NLP Smart Routing (ONNX Runtime INT8)
> **Кейс:** Автоматическая классификация и маршрутизация обращений абонентов в контакт-центр (аналог службы 071 / личный кабинет).
> Архитектура: Обучение TextCNN на **PyTorch** ➔ Экспорт в **ONNX** ➔ Динамическое квантование в **INT8** ➔ Инференс на **ONNX Runtime (CPU)** с латентностью < 5 мс.

---

## 📌 1. Бизнес-контекст и решаемая проблема
В крупных телеком-операторах тысячи обращений в день поступают через чат-боты, мобильные приложения и порталы самообслуживания. 
Ручная сортировка операторами первой линии создает задержку (First Response Time) от 30 минут до 2 часов, приводя к недовольству абонентов при авариях.

### Эффект решения:
- **Мгновенная маршрутизация:** Обращение за доли секунды направляется в целевой отдел (*NOC, Биллинг, Роуминг, Продажи*).
- **Приоритизация SLA:** Аварийные сообщения («нет линка», «горит красный LOS») автоматически получают статус `HIGH` и выводятся в топ очереди дежурных инженеров.
- **Экстремальная оптимизация ресурсов:** Не требует дорогих GPU-серверов. Модель работает на стандартном 2-ядерном виртуальном сервере благодаря квантованию INT8.

```
                                                                   ▼

```

## 🛠️ 3. Стек технологий

- **Обучение:** PyTorch (TextCNN с несколькими размерами ядер сверток для детекции bi-gram и tri-gram).
- **Инференс & Оптимизация:** ONNX, ONNX Runtime (`CPUExecutionProvider`), Dynamic Quantization (`QInt8`).
- **Web API:** FastAPI, Pydantic v2, Uvicorn.
- **Развертывание:** Docker (минимальный образ без CUDA и PyTorch в рантайме, размер контейнера < 120 МБ).

## 🚀 4. Быстрый запуск

### 1. Установка окружения
```bash
pip install -r requirements.txt
```

### 2. Обучение, экспорт в ONNX и квантование
```bash
python src/train_and_export_onnx.py
```
*Скрипт обучит модель, экспортирует граф в ONNX, сожмет веса в INT8 и выполнит замер скорости инференса.*

### 3. Запуск инференс-сервера
```bash
python src/serve_onnx.py
```
*Swagger UI: `http://localhost:8002/docs`.*

## 💡 6. Ответы на технические вопросы (Interview Defense)

1. **Почему не развернули большую LLM (например, LLaMA / Mistral)?**
   > *«Для закрытой задачи классификации по 4–10 категориям использование 7B/8B параметров LLM — неоправданная трата денег на железо и задержка ответа 500+ мс. Специализированный TextCNN / RuBERT, квантованный в INT8, дает точность выше 95% при потреблении 50 МБ RAM и латентности 4 миллисекунды на обычном CPU.»*

2. **В чем суть динамического квантования (INT8 Quantization)?**
   > *«Веса модели конвертируются из 32-битных чисел с плавающей точкой (`float32`) в 8-битные целые числа (`int8`). Это дает 4-кратное сжатие объема модели и задействует инструкции векторного ускорения процессора (AVX-512 / VNNI / NEON), многократно ускоряя матричные умножения без заметной потери качества.»*
